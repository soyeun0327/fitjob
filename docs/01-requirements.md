## 1. 배경과 문제

취준생은 채용 사이트에서 주로 직무명으로 검색한다. 이때 두 가지 문제가 있다.

1. **조건이 맞지 않는 공고가 많이 섞인다.** 신입인데 "경력 3년 이상" 공고가, 서울만 원하는데 지방 공고가 함께 나온다. 사용자가 하나씩 열어보며 걸러야 한다.
2. **사이트가 여러 곳으로 흩어져 있다.** 사람인, 고용24, 지자체 일자리 포털 등을 각각 들어가 같은 검색을 반복해야 한다.

## 2. 목표

### 2.1 서비스 목표

- **G1.** 여러 채용 소스의 공고를 한 곳에서 본다.
- **G2.** 사용자가 자신의 상황(신입/경력, 지역, 직무, 기술 등)을 자연어로 말하면 **조건에 맞는 공고만** 보여준다.

### 2.2 포트폴리오 목표

- 클라우드 인프라 직무 지원용으로, **운영 가능한 AWS 인프라를 직접 설계·구축·운영했다**는 것을 증명한다.
- 모든 인프라를 Terraform으로 관리하고, 비용·보안·장애 대응 결정을 문서(ADR)와 수치로 남긴다.

### 2.3 성공 지표

| 지표 | 목표 | 측정 방법 |
|---|---|---|
| 조건 위반 공고 비율 | 0% | RAG 평가셋에서 하드 조건(경력, 지역 등)을 어긴 추천 건수 / 전체 추천 건수 |
| 조건 추출 정확도 | 90% 이상 | 평가셋 질의별 추출 필드 일치율 |
| 채팅 응답 시간 | p95 6초 이하 | CloudWatch 사용자 지표 `ChatLatency` |
| 공고 목록 응답 시간 | p95 500ms 이하 | ALB `TargetResponseTime` |
| 월 가용성 | 99.0% 이상 (운영 단계) | 5xx를 제외한 API 성공 비율 |
| 수집 성공률 | 소스별 일 95% 이상 | `ingestion_source_stats` |
| 데이터 신선도 | 매일 07:00(KST)까지 갱신 | 파이프라인 완료 시각 |
| 월 비용 | 운영 단계 월 $100 이하(목표 약 $82~91), 개발 기간 월 $35 이하 | AWS Budgets, 비용 할당 태그 ([아키텍처 11](02-architecture.md#11-비용-추정-서울-리전-월)) |

## 3. 범위

### 3.1 MVP 포함

- 공식 API·공공데이터 기반 공고 수집 (사람인 채용정보 API, 공공데이터포털 공공기관 채용정보 조회서비스)
- 소스별 공고를 공통 형식으로 정규화, 데이터 품질 검증, 중복 병합, 마감 처리
- 필터 기반 공고 목록·상세 조회 (원문 링크와 출처 표기)
- 자연어 채팅 검색 (조건 추출 → 조건 필터 + 의미 검색)
- 추천 결과 피드백 (좋아요/싫어요)
- 운영 기능: 수집 이력, 알람, 비용 보호용 호출 상한

### 3.2 MVP 제외 (향후 검토)

| 항목 | 제외 이유 |
|---|---|
| 회원가입·로그인 | 범위 축소, 인프라에 집중 ([ADR-008](10-adr.md)) |
| 관심 공고 저장, 새 공고 알림 | 로그인 필요 |
| 이력서 분석·매칭 점수 | 개인정보 처리 범위 확대 |
| 잡코리아 연동 | API가 공공기관·학교 우선 제공이라 개인 승인 가능성 낮음 |
| 고용24 OPEN API 연동 | 채용정보는 개인 신청으로 받을 수 없음 ([ADR-013](10-adr.md#adr-013-두-번째-수집-소스로-공공기관-채용정보-조회서비스를-쓴다)) |
| 웹 크롤링 | 법적 리스크 ([ADR-001](10-adr.md)) |
| 모바일 앱 | 반응형 웹으로 대체 |
| 실시간 스트리밍 응답(SSE) | P2로 미룸 |

## 4. 사용자

### 4.1 페르소나

| 페르소나 | 상황 | 주요 니즈 |
|---|---|---|
| P1. 신입 취준생 | 컴공 졸업 예정, 서울·경기 희망 | 신입이 실제로 지원 가능한 공고만 보고 싶다 |
| P2. 직무 전환자 | QA 3년차, 인프라 직무로 이직 희망 | "QA 경력 3년, 클라우드 인프라" 같은 복합 조건 검색 |
| P3. 지역 제한 구직자 | 부산 거주, 이사 불가 | 특정 지역 공고만, 마감 임박순으로 |

### 4.2 사용자 스토리

| ID | 스토리 |
|---|---|
| US-01 | 신입 취준생으로서, "서울 신입 백엔드 공고"라고 입력하면 경력 전용 공고가 빠진 목록을 받고 싶다. |
| US-02 | 구직자로서, 받은 결과에 어떤 조건이 적용됐는지 보고, 필요 없는 조건을 지워서 다시 검색하고 싶다. |
| US-03 | 구직자로서, "그중에 정규직만"처럼 이어서 조건을 좁히고 싶다. |
| US-04 | 구직자로서, 채팅 없이 필터만으로 공고 목록을 훑어보고 싶다. |
| US-05 | 구직자로서, 공고가 어느 사이트 것인지 알고 원문으로 바로 이동하고 싶다. |
| US-06 | 구직자로서, 결과가 0건이면 어떤 조건을 풀면 좋을지 제안받고 싶다. |
| US-07 | 운영자로서, 매일 수집이 성공했는지, 실패하면 왜 실패했는지 알고 싶다. |
| US-08 | 운영자로서, 비용이 갑자기 늘면 바로 알림을 받고 싶다. |

## 5. 기능 요구사항

우선순위: **P0** MVP 필수 · **P1** MVP 권장 · **P2** 이후

### 5.1 수집 (FR-C)

| ID | 요구사항 | 우선 | 수용 기준 |
|---|---|---|---|
| FR-C01 | 사람인 채용정보 API에서 공고를 매일 1회 수집한다. | P0 | 매일 05:00 KST에 시작, 원본 응답을 S3 `raw/`에 저장 |
| FR-C02 | 공공기관 채용정보 조회서비스(공공데이터포털, 잡알리오 데이터)에서 공고를 매일 1회 수집한다. | P0 | 위와 동일. API 승인 순서에 따라 먼저 승인된 소스부터 구현 ([ADR-013](10-adr.md#adr-013-두-번째-수집-소스로-공공기관-채용정보-조회서비스를-쓴다)) |
| FR-C03 | 소스별 데이터를 공통 스키마로 정규화한다. | P0 | 경력 구분, 시·도, 직무 카테고리, 고용형태, 학력이 표준 코드로 변환됨 |
| FR-C04 | 정규화 시 데이터 품질 규칙을 검사하고, 위반 레코드는 격리·기록한다. | P0 | 규칙 위반은 `data_quality_issues`에 기록, ERROR 등급은 적재 제외 |
| FR-C05 | 서로 다른 소스의 동일 공고를 하나로 병합한다. | P1 | 지문(fingerprint)이 같으면 대표 공고 1건만 검색 대상 |
| FR-C06 | 마감되었거나 소스에서 사라진 공고를 비활성화한다. | P0 | 검색·채팅 결과에 `CLOSED` 공고 0건 |
| FR-C07 | 소스 호출 실패 시 재시도하고, 최종 실패하면 알린다. | P0 | 지수 백오프 3회 재시도, 실패 시 SNS 메일 |
| FR-C08 | 신규·변경·삭제 공고를 Knowledge Base에 동기화한다. | P0 | 수집 완료 후 동기화 작업 실행, 결과를 `ingestion_runs`에 기록 |
| FR-C09 | 같은 날짜로 파이프라인을 다시 실행해도 결과가 같다(멱등). | P0 | 재실행 시 공고 중복 생성 없음 |

### 5.2 공고 목록·상세 (FR-S)

| ID | 요구사항 | 우선 | 수용 기준 |
|---|---|---|---|
| FR-S01 | 필터로 공고 목록을 조회한다. | P0 | 경력, 지역, 직무, 고용형태, 마감 기한, 소스, 키워드 필터와 정렬(마감순/최신순), 페이지 지원 |
| FR-S02 | 공고 상세에 요약 정보, 원문 링크, 출처를 보여준다. | P0 | 모든 공고에 출처명과 원문 URL 표시 |
| FR-S03 | 데이터 기준 시각(마지막 수집 완료 시각)을 표시한다. | P1 | 화면 상단에 "N시 기준" 표시 |
| FR-S04 | 필터 선택지(직무, 지역, 소스)를 API로 제공한다. | P0 | 화면이 하드코딩 없이 목록을 받아 그림 |

### 5.3 채팅 검색 (FR-CH)

| ID | 요구사항 | 우선 | 수용 기준 |
|---|---|---|---|
| FR-CH01 | 자연어 입력에서 검색 조건을 추출한다. | P0 | 경력 구분·연차, 지역, 직무, 기술, 고용형태, 학력, 마감 기한, 의미 검색어 |
| FR-CH02 | 하드 조건은 메타데이터 필터로 반드시 적용한다. | P0 | 평가셋 기준 조건 위반 0건 |
| FR-CH03 | 추천 결과를 최대 10건 반환한다. | P0 | 결과는 RDS 기준 `ACTIVE` 공고만 |
| FR-CH04 | 각 추천 공고에 매칭 이유를 한 줄로 붙인다. | P1 | 이유는 공고 데이터에 근거. LLM 생성이 실패하거나 `reasons_mode = template`이면 공고 필드로 만든 템플릿 이유로 대체해, 이유가 빠진 결과 0건 ([API 명세 5.4](04-api-spec.md#54-매칭-이유-생성)) |
| FR-CH05 | 적용된 조건을 응답에 포함하고, 화면에서 조건을 지우고 재검색할 수 있다. | P1 | 응답에 `applied_filters` 포함 |
| FR-CH06 | 같은 세션의 직전 대화를 반영해 후속 질문을 처리한다. | P1 | "그중에 서울만" 같은 질의가 이전 조건에 더해짐 |
| FR-CH07 | 결과가 0건이면 완화할 조건을 제안한다. | P1 | 응답에 `suggestions` 포함 |
| FR-CH08 | 공고에 없는 정보를 지어내지 않는다. | P0 | 답변 문장은 검색된 공고 필드만 근거, 평가셋 검수 |
| FR-CH09 | 채용과 무관한 질문, 프롬프트 인젝션 시도는 정중히 거절한다. | P1 | 평가셋의 무관·인젝션 질의 거절률 100% |
| FR-CH10 | LLM 호출이 실패하면 키워드 기반 목록 검색으로 대체 응답한다. | P1 | 응답 `status = DEGRADED`, 사용자에게 안내 문구 |

| NFR-14 | 유지보수성 | AWS 리소스 100% Terraform 관리. 콘솔로 먼저 만든 리소스는 해당 단계 안에 Terraform으로 가져오고, 가져온 뒤에는 콘솔 수동 변경 금지. 상시 스택과 켜져 있는 온디맨드 스택의 드리프트 일일 점검 |
| NFR-15 | 복구 | RDS 시점 복구 RPO 5분, 서비스 복구 RTO 2시간 목표 |
| NFR-16 | 호환성 | 최신 Chrome·Safari·Edge, 모바일 화면 너비(360px)에서 사용 가능 |

## 7. 제약사항

- 클라우드: AWS만 사용, 서울 리전(`ap-northeast-2`)
- 계정: 기존 AWS 계정 사용(신규 크레딧 대상 아님)
- 인력: 1인 개발·운영
- 예산: 운영 단계 월 $100 이하, 개발 기간 월 $35 이하
- 개발 기간 리소스는 작업 시간에만 가동(온디맨드). 앱 개발은 로컬에서 하고 AWS는 인프라 작업과 통합 확인 때만 켠다([ADR-011](10-adr.md#adr-011-개발-기간에는-비싼-리소스를-온디맨드로-운영한다))
- 인프라 구축 방식: 학습을 위해 콘솔로 먼저 만들고 Terraform으로 가져온다([ADR-012](10-adr.md#adr-012-인프라를-콘솔로-먼저-만들고-terraform으로-가져온다))
- 데이터: 공식 API·공공데이터만 사용
- 도메인: 미보유 → Phase 3에서 app·edge 스택을 만들기 전에 Route 53에서 구매 (ALB 인증서와 `origin.<도메인>` 레코드가 도메인을 전제로 함)

## 8. 가정

- 사람인 또는 공공기관 채용정보 조회서비스 중 최소 1곳의 API를 쓸 수 있다.
- MVP 트래픽은 일 수백 명, 채팅 일 1,000회 이하다.
- 활성 공고는 소스 합계 수만 건 수준이다.

## 10. 용어

| 용어 | 설명 |
|---|---|
| RAG | 검색 증강 생성. 질문과 관련된 데이터를 먼저 검색하고, 그 결과를 근거로 답을 만드는 방식 |
| 임베딩 | 글을 숫자 벡터로 바꾼 것. 뜻이 비슷한 글끼리 벡터가 가깝다 |
| Knowledge Base (KB) | Amazon Bedrock의 관리형 RAG 기능. 문서 분할·임베딩·저장·검색을 대신 처리 |
| S3 Vectors | 벡터를 저장·검색하는 S3 기능. KB의 벡터 저장소로 사용 |
| 하드 조건 | 반드시 지켜야 하는 조건(경력 구분, 지역 등). 벡터 유사도가 아니라 필터로 처리 |
| 메타데이터 필터 | 벡터 검색 시 속성값(예: `career_type = NEW`)으로 결과를 거르는 기능 |
| 지문(fingerprint) | 회사명·제목·마감일을 정규화해 만든 해시. 소스 간 중복 판정에 사용 |
| NAT | 프라이빗 서브넷 서버가 외부로 나갈 때 주소를 바꿔주는 장치 |
| 상시 스택 / 온디맨드 스택 | 항상 켜두는 Terraform 스택(bootstrap, network, storage, edge, pipeline)과 작업할 때만 켜는 스택(nat, database, app, observability) |
| replay | 수집을 건너뛰고 S3 `staging/`에 남은 정규화 결과로 적재부터 다시 실행하는 파이프라인 모드 |
